# 03 · 实现方案与踩坑记录

> 本文记录**实际落地**后的实现方案，以及过程中踩过的每一个坑。
> 与 `01-技术路线.md`（理论拆解）、`02-复刻路线.md`（里程碑计划）互补：本文只讲「做成了什么」和「坑在哪里、为什么、怎么修」。

---

## 0. 一句话方案

**CPU 把体素地形打包成「4×4×4 block 的 64-bit 占用掩码 + 逐体素颜色」，上传 GPU 两个 StructuredBuffer；GPU 对每个 block 画一个 4 顶点的 billboard，片元着色器里做 ray-box 求交 + 3D DDA 步进重建真实体素形状，按距离选 LOD，并用 `SV_Depth` 覆写真实命中深度。**

核心思想：**用「每 block 4 顶点 + 片元求交」解耦体素数量与顶点数量**——一个 4 顶点 quad 可代表最多 64 个体素。

### 1.1 模块与文件

| 文件 | 职责 |
|------|------|

### 1.2 数据流

```
[CPU 游戏线程]
  FVoxelMapConfig ──► FVoxelMapGenerator::Generate()
                        ├─ BlockData[]  (每 block 4×uint32：粗掩码+索引 / maskLow / maskHigh / renderStartIndex)
                        └─ VoxelData[]  (每占用体素 1×uint32：RGB24 + extra8)
                              │ Validate() 一致性自检
                              ▼
  UploadVoxelMapToGPU() ── ENQUEUE_RENDER_COMMAND ──► CreateStructuredBuffer + CreateShaderResourceView
[GPU 渲染线程]                                            │
  FVoxelMapSceneViewExtension::PrePostProcessPass_RenderThread()
     ├─ 读 MapCamera 当前位置/朝向，构造 ViewProj + 视锥平面
     ├─ RDG pass：DrawIndexedPrimitive(unit quad, NumInstances = BlockCount)
     │     ├─ MainVS：SV_InstanceID → 解码 block → 展开 billboard → 视锥剔除
     │     └─ MainPS：ray-box → 按距离选 LOD → 3D DDA → 命中体素 → SV_Depth 覆写 → 颜色
     └─ 输出到独立 RT（1024×1024，独立深度缓冲）
```

## 2. 数据层

### 2.1 数据结构（与 GPU 布局严格一致）

```cpp
struct FBlockRenderData          // 每 block 4 个 uint32 = 16 字节
{
    uint32 ShapeLevelAndLocation; // [0..7] = 2×2×2 粗掩码，[8..31] = block 线性索引
    uint32 ShapeMaskLow;          // 4×4×4 64-bit 占用掩码 低 32
    uint32 ShapeMaskHigh;         // 高 32
    uint32 RenderStartIndex;      // 该 block 在 voxel buffer 的起始索引（前缀和）
};
static_assert(sizeof(FBlockRenderData) == 16, ...);

struct FVoxelRenderData          // 每占用体素 1 个 uint32 = 4 字节
{
    uint32 PackedData;            // [0..23] = RGB，[24..31] = material/extra
};
```

### 2.2 位打包约定（CPU 与 shader 必须一致）

```cpp
// 4×4×4 局部坐标 (Lx,Ly,Lz) → 64-bit 掩码位：Lx 最快，Ly 次之，Lz 最慢
bit = (Lx & 3) | ((Ly & 3) << 2) | ((Lz & 3) << 4);

// 2×2×2 粗 cell (Cx,Cy,Cz) → 8-bit 粗掩码位
coarseBit = (Cx & 1) | ((Cy & 1) << 1) | ((Cz & 1) << 2);

// RGB24 + extra8
packed = R | (G << 8) | (B << 16) | (Extra << 24);
```

> ⚠️ 生成器的**遍历顺序必须与位序一致**（Lx 最快 → Ly → Lz），
> 因为 `VoxelData[]` 按掩码位升序写入，shader 里「命中位之前的占用数」要直接用做 `VoxelData` 的 offset。

### 2.3 生成流程（`FVoxelMapGenerator::Generate`）

1. 网格对齐到 4 的倍数（保证所有 block 都是完整 4×4×4）。
2. 逐 block、逐体素采样高度场：`SampleSurfaceHeight(X,Z)` 返回表面高度 `H`，`Y <= (int32)H` 则占用。
   - 地形源 = fBm 噪声（4 octave value noise），可切 `bFlatTerrain` 得到完全平面（调试断裂用）。
3. 占用体素 → 置 64-bit 掩码位 + 置 2×2×2 粗掩码位 + 追加 `VoxelData`（颜色按高度分带：沙→草→岩→雪）。
4. `RenderStartIndex` = 该 block 之前已写入的体素数（天然前缀和）。
5. `Validate()`：自检前缀和、粗掩码重建、体素计数——**bit 打包错误在着色器里极难查，提前拦下**。

## 3. 渲染层

### 3.1 全局 shader 注册（`VoxelMapRendering.cpp`）

```cpp
IMPLEMENT_GLOBAL_SHADER(FVoxelMapVS, "/Project/VoxelMap/VoxelMap.usf", "MainVS", SF_Vertex);
IMPLEMENT_GLOBAL_SHADER(FVoxelMapPS, "/Project/VoxelMap/VoxelMap.usf", "MainPS", SF_Pixel);
```

参数用 `BEGIN_SHADER_PARAMETER_STRUCT` 宏声明（UE5 已弃用旧式 `SetShaderParameter`）。

### 3.2 顶点着色器 `MainVS`

1. `BlockIndex = (BlockData[InstanceID*4+0] >> 8) & 0xFFFFFF`。
2. 解码 `(Bx, By, Bz)` → block 世界空间 AABB：
   ```hlsl
   // 体素 (x,y,z) → 世界 (x,z,y)：体素 Y 是高度，UE 世界 Z 向上
   float3 BlockMin = WorldOrigin + float3(Bx, Bz, By) * BlockSize;
   ```
3. **视锥剔除**（block 包围球 vs 6 平面）。
4. **billboard 展开**：unit quad 沿相机 Right/Up 放大到覆盖投影后的 block。

### 3.3 片元着色器 `MainPS`（核心）

1. **ray-box 求交**（slab 法）求射线进出 block 的 `TEnter/TExit`，未命中 `discard`。
2. **LOD 选择**：`Dist < LOD2Distance(600)` 走完整 4×4×4 DDA，否则走 2×2×2 粗 DDA。
3. **3D DDA（Amanatides-Woo）** 逐 cell 步进，命中第一个占用体素即停。
4. **命中体素颜色**：`ColorIndex = RenderStartIndex + PopCountBelow64(HitBit, MaskLow, MaskHigh)`。
5. **深度覆写**：`SV_Depth = HitClip.z / HitClip.w`（billboard 是平的，必须覆写真实体素深度）。
6. 颜色 + 简单光照（`bDebugDepth` 时输出 `HitT/2000` 灰度，用于诊断）。

### 3.4 RDG pass（`PrePostProcessPass_RenderThread`）

- 独立 RT + 独立 depth-stencil（`FClearValueBinding::DepthFar`，reverse-Z）。
- 深度状态：`TStaticDepthStencilState<true, CF_DepthNearOrEqual>`（reverse-Z 下等价 `GreaterEqual`）。
- 每帧直接读 `MapCamera->GetComponentLocation()`（不缓存，手动拖相机实时反映）。

## 4. 关键约定（改错必翻车）

| 项 | 约定 |
|----|------|
| 坐标映射 | 体素 `(x,y,z)` → 世界 `(x,z,y)`；**体素 Y=高度，UE 世界 Z=向上** |
| 相机朝向 | UE 相机看向 **+X** |
| 视图矩阵 | `FTranslationMatrix(-Eye) * FInverseRotationMatrix(CamRot) * ViewPlanesMatrix`（ViewPlanesMatrix 是轴交换矩阵，漏了必黑屏） |
| 深度 | **reverse-Z**：`FReversedZPerspectiveMatrix`，近=1、远=0；深度比较 = `GreaterEqual`（`CF_DepthNearOrEqual`）；`FClearValueBinding::DepthFar`=0 |
| 视锥平面 | `FConvexVolume` 距离 = `dot(normal, P) - W`，法线朝外，`> radius` 表示在外 |
| 近裁剪面 | Near = 1cm（默认 0.1 会裁掉贴近观察的前景体素） |
| LOD | 只有两级实际生效：`< 600` 完整 DDA，`≥ 600` 粗 2×2×2；**无「整块实心 LOD0」**（会导致过渡断裂） |
| 线程 | `GetRenderTargetResource()` 仅渲染线程；游戏线程用 `GameThread_GetRenderTargetResource()` |

## 5. 踩坑记录（重点）

> 按「现象 → 根因 → 修复」记录。**第 5.3 节的 HitT 断裂是全项目最隐蔽、最难查的一个。**

### 5.1 工程与构建层

#### 坑 1：保存 `.uproject`/关卡报「AssetImportData 外部私有对象」
- **现象**：RT 对象让 `.umap` 序列化失败。
- **根因**：`UTextureRenderTarget2D` 继承的 `AssetImportData` 编辑器子对象被序列化进关卡。
- **修复**：RT 用 `RF_Transient`，并 `#if WITH_EDITORONLY_DATA` 下 `AssetImportData = nullptr`。

#### 坑 2：shader 断言「Shader type loaded after engine init」
- **现象**：注册自定义全局 shader 时崩溃。
- **根因**：默认 `LoadingPhase` 太晚，shader 在引擎初始化后才注册。
- **修复**：`.uproject` 里模块 `"LoadingPhase": "PostConfigInit"`。

#### 坑 3：`ISceneViewExtension` 纯虚函数缺 `BeginRenderViewFamily`
- **现象**：链接报错（抽象类未实现全部纯虚函数）。
- **修复**：补空实现 `BeginRenderViewFamily`（连同 `SetupViewFamily`/`SetupView`）。

#### 坑 4：`PostProcess/PostProcessing.h` 头文件不存在
- **修复**：删掉该 include（用 `SceneViewExtension.h` 已足够）。

#### 坑 5：shader 全局变量名必须与 `FParameters` 成员名**逐字符一致**
- **现象**：RT 全黑 / 参数静默未绑定，无任何报错。
- **根因**：`SHADER_PARAMETER_STRUCT` 按**成员名**绑定 `.usf` 里的同名全局变量；拼写不一致时静默失效。
- **教训**：这是「无报错、结果全错」的典型，改名后务必核对 `.usf` 侧。

#### 坑 6：UE 5.4 删除了旧 RHI API
- **现象**：`RHICreateStructuredBuffer` / `RHICreateShaderResourceView` 编译报弃用/不存在。
- **修复**：改用 `RHICmdList.CreateStructuredBuffer` / `RHICmdList.CreateShaderResourceView`。

#### 坑 7：`RegisterExternalBuffer` 需要 `FRDGPooledBuffer`
- **现象**：想把 RHI 缓冲直接注册进 RDG 失败。
- **修复**：直接用 `SHADER_PARAMETER_SRV(StructuredBuffer<uint>, ...)` + RHI SRV，绕开 RDG buffer 封装。

#### 坑 8：LNK1104 无法打开 DLL
- **现象**：链接失败，DLL 被占用。
- **根因**：编辑器崩溃后残留 `CrashReportClientEditor` 进程锁着 DLL。
- **修复**：杀掉残留进程再重编。

#### 坑 9：导出 RT 崩溃 `check(IsInRenderingThread())`
- **现象**：CallInEditor 按钮导出 RT 崩溃。
- **根因**：`GetRenderTargetResource()` 只能在渲染线程调用。
- **修复**：游戏线程用 `GameThread_GetRenderTargetResource()`，并先 `FlushRenderingCommands()`。

### 5.2 数据与布局层

#### 坑 10：生成器遍历顺序与位序不一致 → 颜色错乱
- **根因**：`VoxelData[]` 必须按掩码位升序写入，shader 才可用 `PopCountBelow64` 直接当 offset。
- **修复**：生成器遍历 `Lz → Ly → Lx`（Lx 最快），与 `bit = (Lx&3)|((Ly&3)<<2)|((Lz&3)<<4)` 严格对应。

#### 坑 11：粗掩码重建对不上
- **修复**：`Validate()` 里重建 2×2×2 粗掩码（8 个体素掩码的 OR）与存储值比对，提前拦下打包错误。

#### 坑 12：网格尺寸不是 4 的倍数
- **修复**：`Align4()` 把 `GridSize` 对齐到 4 的倍数，保证所有 block 都是完整 4×4×4。

### 5.3 渲染正确性层（核心）

#### 坑 13：RT 全黑
- **根因**：视图矩阵漏了 `ViewPlanesMatrix`（轴交换矩阵），且矩阵乘法顺序错。
- **修复**：严格按 `SceneView.cpp` 的构造：
  ```cpp
  FMatrix ViewMatrix = FTranslationMatrix(-Eye) * FInverseRotationMatrix(CamRot) * ViewPlanesMatrix;
  ```
  `ViewPlanesMatrix` 是把「UE 相机看 +X」的坐标系轴交换到标准投影坐标的关键。

#### 坑 14：手动拖动相机 RT 不更新
- **根因**：早期把相机位置缓存成成员，只在地形重建时刷新。
- **修复**：渲染线程每帧直接读 `MapCamera->GetComponentLocation()/GetComponentRotation()`。

#### 坑 15：视锥剔除反了（块在视野内却消失）
- **根因**：`FConvexVolume` 的平面符号约定搞反。
- **修复**：`GetViewFrustumBounds` 给的平面法线朝外，距离 = `dot(normal, P) - W`；shader 里
  ```hlsl
  if (dot(FrustumPlanes[i].xyz, BlockCenter) - FrustumPlanes[i].w > BlockRadius) cull;
  ```
  即「距离 > 包围球半径」表示完全在外才剔除。

#### 坑 16：深绿色透出黄色体素（颜色穿透）
- **现象**：相邻 block 之间颜色互相穿透、串色。
- **根因**：billboard 固定尺寸太小（早期 0.9×），没覆盖 block 投影的完整轮廓，导致相邻 block 的 billboard 在接缝处不重叠，部分像素漏渲染/错渲染。
- **修复**：billboard 尺寸改为**距离自适应**，覆盖 block 包围球投影的完整轮廓：
  ```hlsl
  float HalfSize = BlockRadius * CamDist / max(CamDist - BlockRadius, 0.0001);
  HalfSize = min(HalfSize, BlockSize * 1.5) * BillboardHalfSizeScale; // 默认 1.1 留余量
  ```
  数学依据：block 最近角点的透视投影偏移 = `BlockRadius / (CamDist - BlockRadius)`，上式恰好覆盖它。

#### 坑 17：部分体素顶面偏暗
- **根因**：DDA 首个 cell 直接命中时，`CellHitNormal` 还是 `(0,0,0)`，光照算错。
- **修复**：由 ray-box 的 `TMin` **最大轴**初始化 `EntryNormal`（射线进入 block 的面），首个 cell 命中时用它。

#### 坑 18：LOD 过渡断裂（整块实心 LOD0）
- **根因**：原「LOD0 = 整块实心」会把 block 的空区域也渲染出来，远近切换处出现断层。
- **修复**：合并 LOD0/LOD1——远距离用 2×2×2 粗掩码 DDA，不再用整块实心。

#### 坑 19：⭐ 断裂 / 黑色缝隙（全项目最难查的一个）
- **现象**：地形表面出现**规则的 1px 黑色缝隙网格**（横竖都有），间距约一个体素到几个体素。
- **排查过程（完整还原）**：
  1. 用 `ExportRenderTargetToCSV()` 导出 1024×1024 RT 像素到 `rt_dump.csv`。
  2. 像素级分析发现：缝隙不是「随机噪点」，而是规则网格；关键像素 `x=241 → lum=2`、`x=260 → lum=6`，邻域 `x=242 → lum=37`、`x=261 → lum=37`。
  3. **决定性判据**：缝隙是 `lum 2~6`（**渲染了但极暗**），**不是 `lum 0`（丢弃）**。若是丢弃，根因在 ray-box/DDA 漏判；若渲染了但暗，根因在 `HitT` 计算错误。
  4. 写 CPU 参考实现（`ref/Program.cs`）逐像素复现 shader 的 ray-box+DDA，与暴力遍历对照——**确认 DDA 不漏体素**（401 条射线仅 1 条不一致且是暴力步长问题），排除 DDA。
  5. 逐行核对 shader，定位到 `HitT` 的**基准混用**。
- **根因**（`Shaders/VoxelMap.usf`）：
  ```hlsl
  // TMax 是「相对 block 入口」的距离（LocalPos 是相对 block 的本地坐标）
  float3 TMax = (NextBoundary - LocalPos) / VoxelDir;

  float TCurrent = TEnter;  // ❌ TEnter 是「相对相机」的绝对距离
  ...
  TCurrent = TMax.x;        // ❌ 又被赋成相对入口的距离
  ...
  HitT = TCurrent;          // ❌ 两套基准混用
  ```
  结果：射线进入 block 后**第二个及以后命中的体素**，`HitT` 是「相对入口」的小数值（~10~40 单位），而非「相对相机」的绝对距离。它同时毒害两处：
  - 调试灰度 `HitT / 2000` → 极暗 → 看起来像黑缝；
  - 深度覆写 `CameraPos + RayDir * HitT` → 错位 → 遮挡错误 → 规则断裂。
- **修复**：
  ```hlsl
  // TMax 是相对 block 入口的距离，TCurrent 必须也从 0 起算；
  // 命中距离 HitT = TEnter + TCurrent（绝对）
  float TCurrent = 0.0;      // 原：float TCurrent = TEnter;
  ...
  HitT = TEnter + TCurrent;  // 原：HitT = TCurrent;
  ```
  两处 LOD 路径都要改。
- **教训**：
  - 「黑缝」要区分**丢弃（lum=0）**还是**渲染但暗（lum>0）**，两者根因完全不同。
  - 一条射线沿途的距离量必须统一基准（相对相机 or 相对 block 入口），混用是最隐蔽的 bug。
  - 用 **CPU 参考实现对照暴力遍历**是排查「算法是否漏判」的高性价比手段。

#### 坑 20：近裁剪面裁掉前景体素
- **根因**：默认 Near=0.1，贴近观察时前景体素被裁。
- **修复**：Near = 1cm（`FReversedZPerspectiveMatrix(..., 1.0f, 100000.0f)`）。

### 5.4 调试方法论（可复用）

| 手段 | 用途 |
|------|------|
| `bDebugDepth` 灰度输出（`HitT/2000`） | 验证 ray-box/DDA 算出的命中距离是否正确（近=黑，远=白） |
| `bFlatTerrain` 平面地形 | 排除「断裂来自地形生成」的干扰项，隔离渲染 bug |
| `ExportRenderTargetToCSV()` | 把 RT 逐像素导出，做精确像素级分析（区分丢弃 vs 渲染但暗） |
| 视觉模型读图 | 看大块结构；但对 CSV 需先转 PNG（本项目转成「黑缝标红」的 `rt_highlight.png`） |
| CPU 参考实现（`ref/Program.cs`） | 精确复现 shader 的 ray-box+DDA，与暴力遍历对照，验证算法正确性 |
| `Validate()` 一致性自检 | 上传 GPU 前拦下 bit 打包/前缀和错误 |

> `ref/Program.cs` 用 UE 自带的 dotnet 6.0.302 即可跑：`dotnet run --project ref/ref.csproj`。
