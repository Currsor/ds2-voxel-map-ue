## 0. 背景与设计目标

- 相比《死亡搁浅 1》的 2D 地图，本作地图**完全 3D**，用于送货前的路线规划。
- 核心诉求：既要「全 3D 视角」又要「精确还原地形」，因此选择**体素（Voxel）**方案——对原始游戏资产做「下采样」，无需额外美术资产，又能忠实反映真实地形。

---

## 1. 数据采集与体素化（预处理 / Preprocessing）

从真实游戏资产中「扫描」地形并转成体素数据，使用多趟不同角度的渲染（multi-pass）捕捉地形：

1. **Hemisphere Pass（半球遍历）**：相机沿半球面分布、朝向地形中心，捕捉地形表面。
2. **XYZ Slice Pass（三轴切片遍历）**：相机沿 X/Y/Z 三轴分布，做「正交」切片捕捉。

两趟之后，将捕捉到的点**重采样为均匀点网格（uniform point grid）**，适配后续体素渲染。

> demo 阶段可简化为两种地形源：**高度图 + 颜色图**，以及**程序化噪声地形**（Unity 参考实现用 Job System + Burst 并行生成）。

---

## 2. 数据存储结构（Data Layout）

层级：**World / Q-PID Region → Chunk → Voxel Block → Voxel**。

- **Voxel Block** 是最小可渲染单元，内部是 **4×4×4 = 最多 64 个体素**。
- 选 4×4×4 的关键理由：**一个 block 的占用状态恰好用一个 64-bit 位掩码表示**。
- 每个 voxel 有自己的属性（颜色、粗糙度等）。

对应两份 GPU 结构化缓冲（StructuredBuffer）：

### (a) Per-Block Shape Buffer —— `BlockRenderData`（每 block 4 个 uint32）

```cpp
struct BlockRenderData {
    uint32 shapeLevelAndLocation;  // 前 8 bit = 2×2×2 粗网格占用，其余 bit = block 本地位置索引
    uint32 shapeMaskLow;           // 64-bit 占用掩码的低 32 位（4×4×4 详细占用）
    uint32 shapeMaskHigh;          // 64-bit 占用掩码的高 32 位
    uint32 renderStartIndex;       // 该 block 在 render data buffer 中的起始索引
};
```

### (b) Per-Voxel Render Buffer —— `VoxelRenderData`（每 voxel 1 个 uint32）

```cpp
struct VoxelRenderData { uint32 packedData; };
// RGB 占 24 bit，材质/额外信息占 8 bit
```

关键优化：**只有「存在」的体素才写入 render buffer**，大幅节省显存。

## 3. 渲染管线（GPU Rendering Pipeline）

全图有**数千万体素**，逐个体素建 mesh 不现实（尤其地形还会因「虚爆 voidout」变形）。解决方案是**把体素渲染成公告板（billboard quad）**，把成本从顶点阶段转移到片元阶段：

- 使用实例化绘制（Unity 参考用 `Graphics.DrawMeshInstancedProcedural`），每 block 仅 **4 个顶点**，却可代表最多 64 个体素。
- 每个 quad 的着色器通过 **光线-包围盒求交（ray-box intersection）** 重建真实体素形状，丢弃体素体积外的像素。

### 顶点着色器（Vertex Shader）

- 按 instance ID 读取一个 `BlockRenderData`，解码 block 位置 → 重建世界空间包围盒。
- 处理**揭示动画**（如从地面升起 + 回弹偏移）。
- 沿相机 Right/Up 向量把 quad 展开到足以覆盖投影后的体素块（billboard 尺寸 ≈ block size × 3）。
- 顶点阶段**不感知单个 voxel**，只重建 block 位置与屏幕朝向面片。

### 片元着色器（Fragment Shader）

1. 从相机向像素发射射线，读 block 数据、重建包围盒。
2. **Ray Traversal**：根据距离选择 LOD 级别，遍历体素做命中测试（Level 2 用 **3D DDA** 算法逐 cell 前进，命中即停）。
3. **计算命中体素偏移**：统计 4×4×4 掩码中命中体素之前的占用数 → `renderStartIndex + offset` 取到对应 `VoxelRenderData`。
4. **深度覆写**：因为真实网格是平的 billboard，需把深度写为实际命中体素的深度。
5. 解码材质、计算体素 AO 与光照，输出颜色 + 深度。

---

## 4. LOD（细节层级）

把多个体素打包进一个 billboard 后，着色器按相机距离决定评估精度，同一 block 的掩码支持三级：

| 级别 | 评估内容 | 用途 |
|------|----------|------|
| Level 0 | 整个 block 包围盒 | 远距离，看不出体素细节 |
| Level 1 | 2×2×2 粗网格（shapeLevelAndLocation 前 8 bit） | 中等距离 |
| Level 2 | 完整 4×4×4 占用掩码（64 bit） | 近距离，判定命中具体 voxel |

好处：顶点压力进一步降低，LOD 选择与切换更简单。

---

## 5. 附加效果（参考实现中复现）

- **陨石坑 / 虚爆坑（Crater Effect）**：指定 XZ 位置、半径、过渡宽度、深度，下沉地形，边界做平滑混合。
- **揭示动画（Reveal Animation）**：从起点向外扩散，着色器按 block 到中心距离决定隐藏/升起/完全可见。
- **形状掩码（Shape Mask）**：生成阶段限制地形轮廓，避免总是矩形。
- **LOD 过渡抖动（Dithering）**：参考实现作者实测认为抖动**不适合**体素渲染，此方向待研究。
- **边界淡出（Boundary Fade-Out）**：原版中靠近相机的体素会「缩小后消失」；作者推测与 LOD 过渡相关（可能含 voxel shrink 行为，让近距剔除更平滑）。

---

## 6. 未来工作 / 优化方向

- **构建时间优化**：用 sort-and-reduce 流水线让 block 聚合更并行友好，加速 render data 构建。
- **GPU 视锥剔除**：对不在视锥内的 quad 做 GPU frustum culling，减少无效 draw call。

---

## 一句话总结

**路线 = 多角度扫描资产做体素化 → 4×4×4 block 的 64-bit 掩码数据结构 → 实例化 billboard + 片元级 ray-box/DDA 体素重建 → 三级掩码 LOD → 深度覆写与动画/变形等效果。**

核心思想：用「4 顶点/block 的公告板 + 片元求交」来**解耦体素数量与顶点数量**。
