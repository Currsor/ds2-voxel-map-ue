# 02 · 复刻路线（Unreal Engine）

> 目标：核心渲染 demo（体素数据 + billboard 光追渲染 + LOD）。不含完整地图 UI。
> 引擎：UE 5.4 / 5.5 **预编译版**（无需源码构建）。

---

## 先定架构：三条实现路径

| 路径 | 做法 | 优点 | 缺点 | 适合 |
|------|------|------|------|------|
| **A. 自定义 Global Shader + RDG（推荐）** | 写 `.usf` + `FGlobalShader` + RenderGraph 自定义 pass，StructuredBuffer 传数据，实例化 quad | 100% 还原原方案、控制力最强、可做深度覆写 | 要写 C++ + HLSL，工程量最大 | 想真正吃透并复刻技术 |
| **B. Niagara + Material + Data Texture** | Niagara 实例化 billboard 粒子，材质里用 Custom HLSL 读编码成纹理的 block 数据做 ray-box | 免去整套 shader 工程，见效快 | 材质节点/纹理精度受限，深度覆写别扭 | 快速验证效果 |
| **C. HISM + Per-Instance Custom Data** | InstancedStaticMesh + 每实例 4 个 float（maskLow/maskHigh/location/renderIndex） | 最省事 | 每实例数据少、位操作麻烦、LOD 受限 | 先跑通再迁移 |

> **建议走 A**。核心 demo 的目标就是「体素数据 → billboard → 片元求交 → LOD」，A 路径最贴合原演讲。B/C 可作为中间验证。

---

## M0 · 工程骨架（半天）

- 新建 **C++ 工程**（Blueprint-only 做不了自定义 shader），UE 5.4/5.5。
- 模块 `Build.cs` 加上依赖：`RenderCore`、`Renderer`、`RHI`、`Projects`。
- 注册 shader 目录映射，让引擎找到 `.usf`：

```cpp
AddShaderSourceDirectoryMapping(TEXT("/Plugin/VoxelMap"), FPaths::Combine(PluginDir, TEXT("Shaders")));
```

- 渲染目标：**独立的 `UTextureRenderTarget2D` + 独立相机**（模拟游戏里「地图 UI 是独立场景」），自带独立深度缓冲，避免与主场景渲染打架，也绕开深度 prepass 冲突。

---

## M1 · 体素数据生成（CPU，1–2 天）

定义两份数据结构（对齐原方案）：

```cpp
struct FBlockRenderData {           // 每 block 4×uint32
    uint32 ShapeLevelAndLocation;   // 前 8 bit = 2×2×2 粗网格占用，其余 = block 本地索引
    uint32 ShapeMaskLow;            // 4×4×4 64-bit 占用 低 32
    uint32 ShapeMaskHigh;           // 高 32
    uint32 RenderStartIndex;        // 在 voxel buffer 的起始索引
};
struct FVoxelRenderData { uint32 PackedData; }; // RGB 24bit + 材质/extra 8bit
```

生成流程（demo 用高度图+颜色图，或 FastNoise2 程序化）：

1. 采样地形源 → 得到每个 voxel 坐标。
2. voxel → **block 坐标 + 局部 bit index**：`block = voxel / 4`，`bit = (x&3) | ((y&3)<<2) | ((z&3)<<4)`（按选定的 4×4×4 排布）。
3. 构建 **64-bit 占用掩码** + **2×2×2 粗掩码**。
4. **前缀和（prefix sum）** 计算每个 block 的 `RenderStartIndex`。
5. **只有占用 voxel 写入** `VoxelRenderData` 数组（省显存）。

---

## M2 · 数据上传 GPU（半天）

- 两个 StructuredBuffer（RHI 的 `FStructuredBufferRHIRef`，或 RDG 的 `FRDGBuffer` + `CreateStructuredDesc(sizeof(uint32), NumElements)`）：
  - `BlockDataBuffer`：`NumElements = BlockCount * 4`
  - `VoxelRenderDataBuffer`：`NumElements = OccupiedVoxelCount`
- 用 `RHICreateStructuredBuffer` / `QueueBufferUpload` 上传 uint32 数组。
- 起步可先用**直接 RHI 路径**（`SetShaderParameters` + `DrawIndexedPrimitive`），跑通后再切 RDG 便于集成。

---

## M3 · 顶点着色器（1 天）

写 `VoxelMap.usf` 的 `MainVS`：

1. `BlockDataBuffer[SV_InstanceID * 4 + 0]` 读取 `ShapeLevelAndLocation`，解码 block 位置 → 重建世界空间包围盒。
2. 用相机 Right/Up 向量把 **unit quad 展开成面向屏幕的 billboard**（尺寸 ≈ block bounds × 3，保证覆盖投影后的体素块）。
3. 把 `worldPos`、`blockBounds`、`BlockIndex` 传给片元着色器。

绘制方式：**一个 unit quad 网格（4 顶点 / 6 索引）+ `DrawIndexedPrimitive(NumInstances = BlockCount)`**，`SV_InstanceID` 即 block 索引——这是「4 顶点代表最多 64 体素」的关键。

---

## M4 · 片元着色器（核心，2–3 天）

`MainPS` 流程（照搬博客伪代码）：

1. 从相机到像素位置生成射线，读 block 数据、重建包围盒。
2. **ray-box 求交**，未命中 `discard`。
3. **LOD 选择**（按相机距离）：Level 0 用包围盒 / Level 1 用 2×2×2 / Level 2 用 4×4×4。
4. Level 2 用 **3D DDA** 逐 cell 步进，命中第一个占用 voxel 即停。
5. **统计命中 voxel 之前的占用数** → `RenderStartIndex + offset` 取 `VoxelRenderData`。
6. **深度覆写 `SV_Depth`**：写真实命中体素的深度（billboard 是平的，不覆写会错）。
7. 解码颜色，加简单 AO + 光照。

> HLSL 位运算注意：占用掩码是 uint32 存进 StructuredBuffer，用 `asuint()` 取回；64-bit mask 拆成两个 32 位分别操作。

---

## M5 · 集成与相机（1 天）

- 独立 RT + 轨道/自由相机，逐帧（或数据变化时）渲染。
- 验证：深度正确、遮挡正确、LOD 切换正确、颜色/AO 正常。
- 性能基线：目标是「百万级 voxel 稳定 60+ FPS」。

---

## M6 · 优化与打磨（可选，1–2 天）

- **视锥剔除**（先 CPU，后 GPU frustum culling，减少无效 draw）。
- 控制 overdraw（billboard 膨胀过大 = 片元浪费；按距离调 billboard 尺寸）。
- LOD 过渡（原演讲可能有「voxel shrink」行为，后续研究）。
- 附加效果：陨石坑（voidout 变形）、揭示动画、边界淡出。

---

## 关键坑位提醒

1. **深度覆写**：写 `SV_Depth` 会禁用 early-Z 优化；独立 RT 场景下影响小，主场景合入时需特别处理。
2. **shader 参数**：`FGlobalShader` 必须用 `SHADER_PARAMETER_STRUCT` / `SHADER_PARAMETER_RDG_BUFFER_SRV` 宏绑定，旧式 `SetShaderParameter` 已不适用。
3. **unit quad 要自己构造**：UE 没有现成「无 mesh 的实例化 billboard」，需自建 4 顶点几何 + 索引缓冲。
4. **瓶颈在片元**：4 顶点/block 后，性能主要取决于 billboard 覆盖的像素量 → 远距离 block 一定要走 Level 0/1 少算。
5. **独立地图相机**：原版是地图 UI（独立场景），一开始就独立 RT 会省掉大量和主渲染器的集成成本。

---

## 建议推进顺序

**M0 → M1 → M2 → M4（先 M3 做一个最简「实心方块」跑通管线）→ M3 完整 → M5 → M6**

即先打通「数据 → GPU → 一个方块正确显示」，再逐步上 DDA、LOD、深度覆写。
